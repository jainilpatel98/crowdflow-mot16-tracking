MOT RE-ID / SIAMESE NETWORK PLAN

Date: 2026-03-23

Purpose:
Plan the identity-preservation part of the MOT project: how to keep the same person under the same ID across frames, through short occlusion, and possibly after a brief disappearance.


1. First, define the real goal correctly

The goal is NOT:

- "if two people wear the same color clothes, give them the same ID"

The real goal IS:

- if the same person disappears and reappears, the tracker should try to recover the same ID
- if two different people look similar, the tracker should avoid merging them into one ID

This matters because color alone is not a reliable identity signal.

Why color alone is dangerous:

- many people in MOT scenes wear dark or similar clothes
- lighting changes make the same clothes look different
- occlusion hides part of the body
- motion blur and low resolution remove detail
- two different pedestrians can have nearly identical color patterns

So the system should not assign IDs by "same color clothes" only.
It should use appearance plus motion plus spatial/temporal constraints.


2. What people commonly do in MOT for ID consistency

From Deep SORT:

- add a deep appearance descriptor to tracking
- combine motion gating with appearance similarity
- keep a gallery of recent appearance embeddings for each track
- match detections to tracks using cosine distance in feature space

Why this is important:

- Deep SORT was one of the key steps from pure IoU/motion tracking toward appearance-aware tracking
- the paper reports fewer identity switches by using a learned association metric instead of geometry alone

From ByteTrack:

- keep more detections during association, including lower-score boxes
- this helps preserve tracks when objects are partially occluded or detector confidence drops

Why this matters:

- some ID switches happen not because appearance matching is weak, but because the detector temporarily drops the person
- recovering low-score detections can reduce fragmentation

From BoT-SORT:

- combine motion, appearance, and camera motion compensation
- use ReID as an additional cue, not the only cue
- improve tracking in crowded scenes and moving-camera scenes

Why this matters:

- this is close to what your current YOLO demo path is already trying to do
- the repo config already enables:
  with_reid: True
  gmc_method: sparseOptFlow

From person Re-ID practice:

- use an embedding model trained for person re-identification
- compare embeddings using cosine distance or another metric-learning distance
- train with losses such as triplet loss or classification-style identity loss
- lightweight and practical models such as OSNet are often used as person Re-ID backbones


3. What a Siamese network means in this project

In this MOT context, a Siamese network is best understood as:

- a network that takes two person crops
- produces embeddings for both
- learns that same-person pairs should be close
- learns that different-person pairs should be far apart

This is useful for:

- re-associating a new detection with an existing inactive track
- deciding whether a person after occlusion is the same person as before
- reducing ID switches in crowded scenes

However, a Siamese network by itself is not the whole tracker.

A complete ID system still needs:

- detector
- motion model
- track life-cycle rules
- gating thresholds
- inactive track memory
- assignment strategy


4. The most important design idea

Do not make identity decisions from appearance only.

The correct design is:

- motion says where the person could plausibly be
- appearance says how visually similar the person is
- time gap says whether reassignment is still believable
- scene logic says whether the reappearance location makes sense

Identity should be reassigned only when these cues agree strongly enough.


5. Recommended architecture options

Option A: Course-safe baseline

- keep the current Faster R-CNN detector
- keep the simple IoU tracker as the baseline
- use this as the understandable reference system

Pros:

- simple to explain
- matches the current notebook story
- low implementation risk

Cons:

- weak identity preservation
- many ID switches under occlusion or crowding


Option B: Practical re-ID upgrade

- keep the current detector
- add an appearance embedding model for person crops
- store one or more embeddings per active or recently lost track
- during association, combine:
  1) motion / IoU gating
  2) appearance cosine similarity
  3) recentness of the track

Pros:

- directly addresses the user-visible problem of ID reassignment
- easier to defend academically than "color matching"
- can still be explained clearly in the report

Cons:

- requires threshold tuning
- may still fail when many pedestrians look similar


Option C: Use BoT-SORT / DeepSORT as the comparison method

- use the YOLO + BoT-SORT notebook as the stronger reference
- or study the DeepSORT baseline notebook as the conceptual template

Pros:

- grounded in established MOT practice
- already aligned with appearance-aware tracking literature

Cons:

- weaker fit if the assignment requires a custom or course-built pipeline
- easier to demo than to explain from first principles unless documented well


6. Recommended project decision

Best planning decision for this repository:

- keep Faster R-CNN + IoU tracker as the official baseline
- add one planned "appearance-aware reassignment" extension
- treat that extension as the Siamese / Re-ID improvement stage
- keep YOLO + BoT-SORT as a benchmark comparison, not the only answer

This gives a clean report story:

1) baseline tracking with geometry only
2) improved tracking with appearance-aware reassignment
3) comparison to a stronger off-the-shelf tracker


7. How the ID reassignment module should work conceptually

Step 1:
- detect pedestrians in the current frame

Step 2:
- predict active track positions using motion

Step 3:
- do normal association for active tracks using motion/IoU first

Step 4:
- keep unmatched tracks in a temporary inactive memory for a limited number of frames

Step 5:
- for each unmatched new detection, extract a person embedding

Step 6:
- compare that embedding against the inactive track gallery

Step 7:
- only restore the old ID if:
  appearance similarity is high enough
  time gap is not too large
  spatial jump is plausible
  there is no stronger competing match

Step 8:
- otherwise create a new ID

This is the key planning idea:

- "reassign old ID only when evidence is strong"
- not "reuse old ID whenever colors look close"


8. What features the appearance model should learn

Good appearance cues:

- upper-body and lower-body texture
- stripe or logo patterns
- bag or backpack presence
- body silhouette
- local texture details
- shoe or trouser contrast when visible

Weak or unstable cues:

- raw average color only
- tiny low-resolution face region
- background around the person crop
- box size alone

If a Siamese or Re-ID model is used, the crop preprocessing should reduce background influence as much as possible.


9. Data plan for a Siamese / Re-ID model

Possible training data sources:

- MOT16 train identities within each sequence
- external person Re-ID datasets if allowed
- a pretrained Re-ID model used without retraining

Most practical plan for this project:

- do not start by training a Siamese model from scratch unless there is enough time
- first use a pretrained person Re-ID model
- then, if required for the class, fine-tune or explain a Siamese/triplet setup as an extension

Why:

- training Re-ID from scratch is a separate project by itself
- pretrained Re-ID models already encode much stronger appearance features than color heuristics


10. Best candidate strategy for this project

Best practical choice:

- use a pretrained person Re-ID backbone such as OSNet
- extract one embedding per person crop
- use cosine similarity
- keep an embedding gallery for each track
- combine appearance with motion gating

Why this is stronger than pure Siamese-from-scratch planning:

- lower risk
- closer to current MOT practice
- easier to compare against DeepSORT / BoT-SORT ideas
- easier to explain in the report


11. What thresholds and rules need planning

The following settings must be planned and later validated:

- active-track match threshold
- inactive-track reactivation threshold
- maximum inactive age before deleting a track
- minimum detection confidence for creating a new track
- whether to use one embedding per track or a gallery of recent embeddings
- whether to use average embedding, best-match embedding, or most-recent embedding

Important design choice:

- reactivation threshold should usually be stricter than ordinary frame-to-frame matching

Reason:

- reassigning an old ID is more dangerous than continuing a stable active track


12. Failure cases we should expect

Failure case 1:
- two people cross each other wearing similar dark clothing

Failure case 2:
- one person becomes fully occluded for too long and reappears far away

Failure case 3:
- detector misses the person for multiple frames, so the track dies too early

Failure case 4:
- crop quality is poor and the appearance embedding becomes noisy

Failure case 5:
- the model overfits to color and fails when illumination changes

This means the report should include an "ID switch analysis" section, not just overall metrics.


13. What to measure for this re-ID extension

Main tracking metrics:

- IDF1
- ID switches
- MOTA
- HOTA if available

Useful qualitative checks:

- same person after short occlusion keeps same ID
- different people with similar clothes do not get merged
- crowded crossings are visually inspected
- moving camera scenes are checked separately from static camera scenes

The most important metric for the Siamese / Re-ID idea is not detector loss.
It is identity preservation, especially IDF1 and ID switches.


14. Practical recommendation for the report wording

Good wording:

- "We add appearance-aware identity reassignment using person Re-ID embeddings."
- "A Siamese / metric-learning view is used to determine whether two detections belong to the same pedestrian."
- "Identity reassignment uses appearance together with motion and temporal gating."

Avoid wording like:

- "same clothes means same ID"

That wording is too weak technically and can be criticized easily.
